# cpc — Core

"calculation + conversion": evaluates math-expression strings with units and unit conversion.
One Rust crate produces three artifacts:
- rlib library (crates.io); public API = `cpc::eval` in `src/lib.rs`.
- CLI binary (`src/main.rs`).
- cdylib WASM module (`wasm_eval`, cfg(target_arch="wasm32")) consumed by the web frontend.

## Source map (`src/`)
- `lib.rs` — entry `eval()`; defines `Number {value: D128, unit: Unit}`, `Token`, `Operator`, `UnaryOperator`, `TextOperator`, `Constant`, `FunctionIdentifier`, `NamedNumber`, `LexerKeyword` + Display for Number.
- `lexer.rs` — `lex()`: string → Vec<Token>.
- `parser.rs` — `parse()`: tokens → `AstNode` (recursive descent).
- `evaluator.rs` — `evaluate()`: AstNode → Number; math/trig helpers.
- `units.rs` — `Unit` enum generated by `create_units!` macro; unit-aware arithmetic + conversion.
- `lookup.rs` — named numbers (million/billion), factorial lookup.
- `main.rs` — CLI arg parsing.

## Invariants
- Units are compile-time only: the generated `Unit` enum is imported by lexer/parser/evaluator; cannot be extended at runtime (see comment on the `create_units!` macro).
- `eval` signature: `eval(input: &str, allow_trailing_operators: bool, verbose: bool) -> Result<Number, String>`. The old `default_degrees`/default-`Unit` argument was removed in 2.0.0.
- Stage errors propagate as strings prefixed by stage: `"Lexing error: …"`, `"Parsing error: …"`, `"Eval error: …"`.
