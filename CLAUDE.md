# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`cpc` ("calculation + conversion") evaluates strings of math with support for units and
conversion between them (e.g. `1 km - 1m` → `999 Meter`). It ships as three things from one
crate:

- A **Rust library** (`rlib`) published to crates.io — public API is `cpc::eval`.
- A **CLI binary** (`src/main.rs`) — `cpc '2h/3 to min'`.
- A **WASM module** (`cdylib`) consumed by the SvelteKit web app in `web/` (deployed to
  cpc.kasper.space via Vercel).

Numbers use 128-bit decimal floating point via the `fastnum` crate (`D128`, constructed with the
`dec128!` macro, imported throughout as `d`). Decimal — not binary — float is deliberate, for
accuracy.

## Commands

```bash
cargo run -- '100ms to s'            # run the CLI
cargo run -- '100ms to s' --verbose  # verbose: prints lexed tokens, parsed AST, timings
cargo test                           # run all tests (most tests live in `mod tests` inside each src file)
cargo build                          # debug build; use --release for the published binary
```

Run a single test by name: `cargo test <substring>` (e.g. `cargo test convert`).

### Web / WASM

The web app depends on the WASM package, which `npm run build-wasm` emits to `/pkg` at the repo
root (referenced from `web/package.json` as `"cpc": "file:../pkg"`). So `dev`/`build` rebuild WASM
first.

```bash
cd web
npm install
npm run dev      # builds WASM (wasm-pack --target bundler) then starts Vite
npm run build    # builds WASM then builds the SvelteKit site
npm run check    # svelte-check type checking
```

## Architecture

`eval()` in `src/lib.rs` is the single entry point that wires a three-stage pipeline; each stage
is its own module and returns `Result<_, String>` so errors propagate up as `"Lexing error: ..."`,
`"Parsing error: ..."`, `"Eval error: ..."`:

1. **`lexer.rs`** — `lex(input, allow_trailing_operators)` turns the raw string into `Vec<Token>`.
   This is where unit words and operator words/phrases (`plus`, `multiplied by`, `÷`, `µs`, etc.)
   are recognized. Input is case-insensitive. The `Token` enum and friends (`Operator`,
   `Constant`, `FunctionIdentifier`, `NamedNumber`, `LexerKeyword`) are defined in `lib.rs`.
2. **`parser.rs`** — `parse(&tokens)` builds an `AstNode` tree via recursive-descent functions
   ordered by precedence (`parse_plus` → `parse_mult_level` → `parse_caret` → `parse_unary_high`
   → `parse_suffix` → `parse_highest`). Precedence changes happen by re-wiring these.
3. **`evaluator.rs`** — `evaluate(&ast)` walks the tree (`evaluate_node`) and produces the final
   `Number`. Math/trig helpers (`factorial`, `sqrt`, `sin`, …) live here.

`Number { value: D128, unit: Unit }` is the value type (in `lib.rs`), and its `Display` impl
chooses singular/plural unit names and formats the decimal.

### Units system (`src/units.rs`)

Units are generated by the `create_units!` macro, which expands into the `Unit` enum plus
`category()`, `weight()`, `singular()`, `plural()` methods. Each unit is declared as
`Variant: (UnitType, weight, "singular", "plural")`. **Weight** is the conversion factor within a
`UnitType` (e.g. if Second = 1, Minute = 60); `get_conversion_factor`/`convert` use it. Because the
generated `Unit` enum is imported by the lexer, parser, and evaluator, units cannot be extended at
runtime — they're compile-time only.

`units.rs` also holds the unit-aware arithmetic (`add`, `subtract`, `multiply`, `divide`, `pow`,
`modulo`) and the "pick the nicest unit to show" logic (`to_ideal_unit`, `convert_to_lowest`).
`lookup.rs` resolves named numbers (`million`, `billion`) and factorial lookups.

### Adding a unit

1. Add the variant to the `create_units!` invocation in `src/units.rs` with its `UnitType`,
   weight, and names.
2. Add a conversion test in `units.rs`'s `mod tests` (pattern: `convert_test(1000.0, Meter, Kilometer) == 1.0`).
3. Register its spelling(s) in `src/lexer.rs` so the word lexes to `Token::Unit(...)`.

## Conventions & gotchas

- **Hard tabs** for indentation (`rustfmt.toml` sets `hard_tabs=true`). Run `cargo fmt`.
- **Rust edition 2024.**
- The `eval` signature is `eval(input: &str, allow_trailing_operators: bool, verbose: bool)`.
  Note: the API example in `README.md` is stale — it shows a 4-argument form with a default
  `Unit::Celsius` parameter that was **removed in 2.0.0**. Trust the source, not that snippet.
- CI: `.github/workflows/test.yml` runs `cargo test` on every push/PR. `deploy.yml` builds and
  deploys `web/` to Vercel on push to `main`. `release.yml` builds release binaries on tag.

## Releasing (from README)

1. Update `CHANGELOG.md`  2. Bump version in `Cargo.toml`  3. `cargo test`
4. Create a git tag `v#.#.#`  5. Add GitHub release notes  6. `cargo publish`
